# Offline résumé-output evaluation

Run `npm run eval:resumes` for a JSON report or `npm run --silent eval:resumes`
for JSON without npm's script header. Run `npm run test:resume-evals` for detector
mutation tests. The ordinary library suite includes the store-free detector tests, while
`test:jobdesk` includes the saved-PDF/approval integration test; CI
runs both the tests and the report on Linux, macOS and Windows.

This first pass is deliberately **offline, synthetic and deterministic**. It
uses the fictional Jordan Rivera résumé, hand-written posting fixtures and
hand-selected assessments/claims. It does not call a model, collect jobs, read a
real installation, upload personal data or submit an application. The owner
service builds genuine saved employer PDFs in a fresh temporary store. The store
and artifacts are removed after evaluation. It never marks visual review passed
or approves the resulting draft; the runner asserts those gates stay pending.

## What is checked

- Independent PDF.js extraction of the **saved bytes**, compared with literal,
  hand-authored complete-document goldens and the renderer's separate text trace.
  Whitespace normalization tolerates wrapping; wording, quantities and order must
  match. Goldens are not generated by the assembler, ranker or evaluator.
- Selected claim IDs, unique selection/snapshots, current reviewed status, exact
  wording, immutable version and source-note consistency; missing PDF claims;
  posting verification/version and artifact checksum.
- Employer-text leakage of source notes, explicit private-review markers and
  injected instructions; extra unsupported prose, incorrect employer attribution
  and omissions are caught by the document golden. PDF metadata, attachments,
  clipping, legibility and malicious PDF execution are not covered by text checks.
- Hand-labelled requirement evidence coverage, separately counting transferable
  evidence and unsupported requirements. Empty evidence lists remain honest gaps;
  they do not count as covered and do not enter the supported-evidence denominator.
  Labels are human-authored fixture judgments, not proof of semantic entailment.
- A supplied recommendation compared with its fixture expectation, including
  deliberately wrong exclusions. This tests the **detector**, not the quality of
  a live model's assessment: the baseline recommendations are scripted inputs.

Mutation tests deliberately introduce revoked/stale/duplicate claims, fabricated
wording and sources, missing/unverified postings, false exclusions, missed
transferable evidence, document omissions, private leaks and incorrect bindings.
One test creates a real replacement PDF containing an invented certification and
injection markers, recomputes its checksum, parses it and still expects rejection.
Invalid PDF bytes must fail extraction. Green goldens alone are insufficient.

## Interpreting the baseline

The initial three-fixture run has 3/3 matching employer documents and 9/9 covered
supported requirement labels with the scripted complete selections. Two credential
requirements remain unsupported. The separate current lexical top-eight shortlist
baseline covers 6/9 supported labels: 4/4 analytics, 1/4 transferable operations,
1/1 planning. This is a small retrieval diagnostic, **not** measured model quality,
a claim of improved production selection, a recruiter score or a hiring prediction.
The three cases do not establish generalization or prompt-injection resistance of
an assistant: no assistant is run. They establish that approved-text assembly
ignores posting instructions and that these output regressions are detectable.

The report keeps deterministic issues, evidence recall and optional advisory review
separate. There is no combined quality score. The next meaningful extension is
more independently labelled cases and a separately authorized model-run adapter,
recording real provider usage, calls, corrections and time per approved packet.
No provider/budget behavior is changed by this patch.

## Optional recruiter-review adapter

`bindRecruiterReview` accepts a separately supplied human/advisory result under
`recruiter-advisory-1`: unsupported implications, missing evidence, relevance and
clarity. Findings must quote the résumé or posting; unsupported implications must
quote the résumé. Cited claim IDs and quotes are checked. It binds to artifact ID,
actual artifact-byte hash, workflow posting hash, computed posting-text hash and
selected claim snapshot hash. A changed binding rejects an old review.

It returns a serializable record explicitly marked `advisoryOnly: true` and
`approvalGranted: false`. No paid judge, DB migration, approval endpoint or automatic
persistence is introduced. A future caller can save this record beside its artifact;
this first-pass runner does not pretend a recruiter has reviewed the résumé.
The evaluator inputs must come from trusted local extraction/current catalog reads;
it is not an authentication boundary for arbitrary model-supplied inputs.

The optional `approvedSearchBrief` input accepts `used` and `current` identities
with `{ briefId, version, contentHash }`, obtained from an approval-validated
search-brief compiler. Mismatched versions invalidate evaluation and advisory review.
It neither invents preferences nor approves a brief. Existing fixtures have no real
user preferences; no production search-brief integration is claimed.

## Reproducibility and environment

Fixtures live in `tests/fixtures/resume-evals.ts`; changes to their hand-authored
expectations require review. Summary output contains synthetic fixture IDs and
issue/claim IDs, not résumé text or source notes. Artifact identifiers, version
stamps and hashes can differ each run; the semantic counts and expectations are
stable. Save reports locally with ordinary stdout redirection if desired.

The PDF parser is a pinned **development-only** dependency supporting the project's
Node 22 minimum. No production renderer/dependency path is altered. Installation
needs the normal package registry; execution needs no network or model credentials.
For environments where `/tmp` lies within Git, set `JOBDESK_TEST_TMPDIR` to a private,
unsynced temporary directory outside Git. This affects test helpers only and does
not weaken the production private-root guard. On POSIX keep paths short enough for
Unix sockets when running the full service suite.
